# 调查工作历史

## 准备

按本机时区解析日期。按 `obsidian-knowledge` 的配置发现规则找到 Vault，找不到时明确说明，不使用固定盘符或用户名。

## 调查顺序

1. 在日期范围内窄查 `wiki/我的经历/`，恢复目标、阻碍、判断、行动与结果。
2. 读取 `成果/知行台/YYYY-MM-DD.md`，打开必要的成果证据。
3. 读取 `raw/codex/knowledge-settlements.json`，核对 `succeeded`、`pending`、`failed` 和 `not-applicable`。
4. 只有发生遗漏、歧义或来源争议时，才窄查 Codex、ChatGPT 或飞书每日来源和 JSONL；飞书结论同时检查同步状态与访问状态。
5. 重要完成声明用当前文件、Git 历史或实际运行状态再次核验。

## 统计口径

- 同项目、同目标的重复会话合并为一项真实任务。
- 统计任务、交付物、Git 提交和知识对象，不把消息数、工具调用或事件数当成工作量。
- `independent` 表示 Git 或实际 Wiki 等独立事实；`target-present` 表示目标存在；`report-only` 表示只有完成报告。
- 项目切换与投入程度只能作为观察，不换算工时或生产力分数。

## 回答

优先呈现已完成任务和产物、正在推进或受阻事项、新增或复用知识、少量可解释数字，以及证据缺口。明确区分知行台历史、当前核实事实和推断。
